# Правовой разбор публикации

Состояние на **20 октября 2026 года**: подготовка лицензий и проверяемых материалов
выполнена; утверждать «все права очищены, можно гарантированно публиковать» пока
нельзя. Причина — конкретные открытые вопросы, а не отсутствие длинного дисклеймера.
Это технический разбор, не заключение юриста по выбранной стране и модели релиза.

Владелец уточнил план: **бесплатные исходники на GitHub**, страна — другая,
конкретная юрисдикция не названа. Поэтому выводов по определённому национальному
праву нет. Отсутствие платы не отменяет условий распространения GPL или чужих
прав; бесплатность также не позволяет добавить запрет на коммерческое
использование получателями. Готовые бинарники сейчас в план публикации не входят.

## Какую лицензию оставляем

Для новых частей приложения — **GPL-3.0-only**, полный неизменённый текст в
[LICENSE](../../LICENSE). Сфера действия подробно определена в
[LICENSE-POLICY.md](../../LICENSE-POLICY.md). Чужие части сохраняют собственные
разрешения: большинство движка GPL-2.0-or-later, SHA-1 GPL-3.0-or-later, шрифты
FlyByWire GPLv3, карта шрифта и графика Freedoom BSD-3-Clause. Нельзя объявить весь
набор MIT, своим исключительным произведением или «без авторских прав».

GPL разрешает и коммерческое распространение при соблюдении условий. Запрет
продажи, модификаций, подачи исков или использования конкурентами не добавляем:
«жёсткая» самодельная лицензия здесь может сама создать нарушение. Сохраняем
исходные условия и делаем обязанности проверяемыми. Отказ от гарантий действует
в пределах применимого права и не запрещает правообладателю предъявлять претензии.

## Главный незакрытый вопрос

У `config.h`, `doom.h`, `doomgeneric.c`, `doomgeneric.h`, `dummy.c`, `mus2mid.h`
нет собственного указания версии GPL; в корне DoomGeneric — текст GPLv2.
Это не равнозначно доказанному GPL-2.0-only и не автоматически разрешение GPLv3.
Соседний файл с «or later» не выдаёт разрешение за автора другого файла.

Если соответствующие части разрешены только под GPLv2, GPLv3-комбинация потребует
другого разрешения. Мы не можем исправить это собственным новым LICENSE или
подписать разрешение за правообладателя. Подтверждение происхождения хешами
не решает вопрос объёма прав. В [реестре](review-register.json) есть точный критерий
закрытия, а в [черновике вопросов](upstream-questions.md) — что требуется выяснить.
Никому не отправлялись сообщения от имени владельца проекта.

Публикация одних исходников тоже является распространением. Формула «выложим
только source, значит несовместимость не важна» здесь не используется. Исходный
архив готов для проверки; его создание не означает разрешения всех вопросов.

## Что проверено и усилено

- Сохранены все исходные уведомления движка; [журнал изменений](../../MODIFICATIONS.md)
  явно описывает семь изменённых файлов и один новый ABI-заголовок с датой уведомления.
- Шрифты сверены с зафиксированной ревизией FlyByWire, вместе поставляются SFD,
  TTF, генератор и GPL. Исключение для шрифтов не выдумывается. Вывод программы
  не становится GPL автоматически: здесь отдельно учитываются формы GPL-шрифта
  и выбранная лицензия новых элементов оформления.
- Картинки README используют Freedoom, без коммерческих ресурсов DOOM. Сохранены
  BSD, имена/кредиты и отдельное описание прав на изображения. Если заменить WAD,
  права на новые снимки нужно проверять заново.
- [Реестр Windows-зависимостей](dependencies-windows.json) фиксирует версии,
  контрольные суммы пакетов, включённые Cargo features, варианты лицензирования,
  вложенные тексты и их хеши. Выбран MIT там, где разрешён; обязательное
  `AND Unicode-3.0` не отброшено.
- Встроенная C HIDAPI имеет отдельные условия: сохраняются четыре вложенных
  уведомления, для нативной части выбран предоставленный BSD-вариант. Заголовок
  её `build.rs` GPL-3.0-or-later отмечен отдельно от пакетной декларации MIT.
  Инвентарь Cargo не выдаётся за доказательство однородной лицензии каждого файла.
- Подготовка архива проверяет совпадение реестра с locked-графом, собирает
  вложенные уведомления с исходными путями и останавливается при неожиданных
  зависимостях/лицензиях/хешах. Это контроль известных материалов, не юридический ИИ.

## GitHub и готовые программы — разные составы поставки

Для исходного репозитория сохраняем лицензии, уведомления, изменения, шрифтовые
исходники/генераторы и сведения о происхождении. Для ZIP берём allowlist, а не
всю рабочую папку. WAD, firmware, SimAppPro, логи, сохранения и секреты не входят.
Игнорирование файлов не удаляет их из уже существующей истории Git. Сейчас в
рабочей папке `.git` отсутствует: чужую/будущую историю эта проверка не охватывает.

Для EXE потребуется отдельная проверка **Corresponding Source** по GPLv3 §1/§6:
точные исходники соответствующей сборки, изменения, скрипты и необходимые части
зависимостей/нативного кода, а не только `Cargo.lock`. Нынешний ZIP содержит
уведомления зависимостей, но не весь их исходный код; это не проверенная полная
поставка исходников к бинарнику. System Libraries и Installation Information
оцениваются для фактической поставки. Уведомления интерактивных интерфейсов по
§5(d), права инструментальной цепочки и runtime тоже проверяются на готовом релизе.

## Что лицензией на код закрыть нельзя

| Вопрос | Что нужно сделать владельцу релиза |
| --- | --- |
| Бренды, похожий авиационный интерфейс, внешний вид Blocks | Оценить реальный интерфейс, название и рекламу для территории публикации. Нет заявления об официальном продукте/одобрении; отсутствие логотипа само по себе не гарантирует отсутствие претензий. |
| Договоры и аппаратный протокол | Проверить собственные условия приобретения/использования устройства и ограничения применимого права. Не поставляем прошивки и программы производителя. |
| Автор/работодатель/контрибьюторы | Подтвердить полномочия на лицензирование; сохранить реальные сведения о вкладах, не выдумывать владельца. ИИ не гарантирует уникальность/охраноспособность каждого фрагмента. |
| Игровые данные | Разрешение движка не распространяется на коммерческие WAD, музыку и изображения. Shareware не означает произвольное право переупаковки. |
| Патенты и обязательные нормы | GPLv3 содержит определённые патентные положения, но не выдаёт разрешение на все чужие патенты и не отменяет обязательное местное право. |

Решение [Tetris Holding v. Xio](https://www.govinfo.gov/content/pkg/USCOURTS-njd-3_09-cv-06115/pdf/USCOURTS-njd-3_09-cv-06115-0.pdf)
показывает, почему новое имя и собственный код не являются универсальным ответом
на претензии к оформлению игры. Применимость к нашей реализации и другой стране
нельзя установить одним сравнением размеров поля.

## Практический порядок перед публикацией

1. Закрыть открытые пункты [реестра](review-register.json) документальными
   разрешениями или оценкой специалиста по интеллектуальной собственности;
   хранить полученные ответы и область их действия. Не выставлять `resolved`
   без ссылки на реальные доказательства.
2. Установить владельца/контакт релиза и подтвердить права на новые вклады.
   Личное имя/адрес сейчас не подставлены автоматически.
3. Запустить `scripts/validate-licenses.ps1`, `scripts/validate-docs.ps1` и
   `scripts/prepare-publication.ps1`. Проверить точный архив и состав файлов.
4. Для GitHub загружать проверенное дерево исходников вместе с уведомлениями,
   без подмены корневого LICENSE стандартной MIT-кнопкой. Перед push отдельно
   проверить фактическую историю/секреты. Публикацию эти скрипты не выполняют.
5. Готовые EXE оформлять отдельной поставкой после проверки её исходников и
   уведомлений; не считать нынешний source-only ZIP достаточным по умолчанию.
